Summary

This page gathers public MUJI references and turns them into a practical redesign guide for the Open Commerce storefront. The goal is a product-first, quiet, utilitarian store experience.

Boundary: do not copy MUJI logos, proprietary imagery, exact copy, or trade dress one-to-one. Translate the observed principles into an original store identity.

Brand Principles To Translate

No-brand quality goods

Product utility should matter more than decorative branding.

Three product rules

  • Selection of materials
  • Streamlining of processes
  • Simplification of packaging

Desired feeling

Quiet, rational, ordinary, practical, confident, and not hype-driven.

Visual Specs Observed

Palette

#ffffff #191919 #363636 #808080 #b3b3b3 #8a3a2d MUSE cedar #5f241b hover #f6f6f6 #ededed

Typography

  • Roboto-like neutral sans for body text.
  • Condensed sans for headings, product titles, and controls.
  • Compact body size around 14px.
  • Restrained uppercase headings around 26px to 30px.

Shape

  • Flat white and light-gray surfaces.
  • Thin borders and minimal shadows.
  • Radius usually 0px to 3px.

Image language

  • Mostly square product images.
  • Clean, centered objects on white or light-gray backgrounds.
  • Seasonal editorial images when they explain a category.

Layout

  • Max content width around 1200px.
  • Modest gutters near 20px.
  • Commerce modules instead of oversized brand statements.

Avoid

  • Dark lifestyle imagery.
  • Heavy gradients and decorative illustration.
  • Oversized hero type for ordinary shop sections.

Component Inventory

The current codebase has a small shared component layer and a lot of route-local storefront markup. The redesign should move repeated public-store UI into small reusable pieces. Admin should also be redesigned, but as a denser operations variant of the same MUSE system.

Keep and restyle

  • AuthStatus: keep session behavior; restyle links/buttons for compact header.
  • ToastProvider and useToast: keep; restyle toast borders and actions.
  • LoadingState: keep API; make skeleton match product-grid placeholders.
  • AccessRequired and RouteError: keep; make them quieter content states.
  • StatusBadge: keep labels/tone logic; restyle to small neutral status chips.
  • AddressFields and CouponFeedback: keep logic; extract only if reuse grows.

Remove or replace

  • Inline duplicated ProductCard markup in home and catalog.
  • MetaRow and the current homepage meta column.
  • Homepage about-band dark manifesto section.
  • .product-card small price-tag overlay.
  • .eyebrow::before decorative line and large negative-tracking headings.
  • Customer use of admin-table, admin-panel, and stack-list.
  • Root footer oversized MUSE wordmark and black brand band.

Build new

  • StoreHeader, PromoBar, CategoryNav, SearchBox.
  • StoreFooter, FooterLinkColumns, NewsletterSignup.
  • StorefrontProductCard, ProductGrid, ProductGridSkeleton.
  • CollectionHeader, CategoryTile, FilterSortBar.
  • ProductGallery, VariantOptionGroup, QuantityStepper, DetailAccordion.
  • OrderSummary, CartLineItem, CustomerOrderTable, PaymentPanel.
  • AdminShell, AdminDataTable, AdminFormSection, AdminKpiBar.

Route file rule keep simple

Route files should keep data loading, mutation handlers, and page-level composition only. Repeated UI belongs in shared components so each route.tsx keeps focusing on one thing.

Admin boundary redesign included

Admin screens are included in the redesign. They should keep operational density and clear tables/forms, but use the same restrained MUSE tokens instead of the current editorial Muse styling. Customer pages should stop borrowing admin table/panel classes.

Data boundary preserve behavior

No Convex schema or checkout/payment logic needs to change for the first redesign pass. The work is presentation, shared components, and route composition.

Current App Fit

What already fits

  • Public routes already cover home, products, product detail, cart, checkout, payment, account, and admin.
  • Core commerce behavior can stay mostly intact.
  • Route files are already reasonably focused.

What changes

  • Replace expressive Muse identity with compact retail navigation.
  • Move visual repetition into shared CSS/components.
  • Make product cards, PDP, cart, and checkout quieter and more utilitarian.

Implementation Plan

Done: design tokens and shared shell are implemented with MUSE cedar, compact typography, retail header, and service footer.
Done: reusable storefront components now cover product cards, quantity stepper, product gallery/detail accordions, and cart line items.
Done: home and product listing routes are redesigned into commerce modules, category/filter controls, and quiet product grids.
Done: product detail route now uses gallery left, purchase panel right, variant buttons, quantity stepper, and detail accordions.
Done: cart and account states are brought into the same system; checkout/payment share the refreshed form, summary, and status styling.
Done: admin screens use the restrained MUSE operational shell treatment without the public marketing footer/category rail.
Done: npm run typecheck, npm run build, and Playwright desktop/mobile screenshot checks passed.

Deferred product work: real search behavior, wishlist, customer reviews, address book management, and richer admin-managed collection modules.

Locked Decisions

  • Redesign includes customer storefront and admin screens.
  • The product/store name remains MUSE.
  • Use adjacent MUSE cedar #8a3a2d instead of MUJI red directly, with hover/dark accent #5f241b.
