Detailed Per-Page Redesign Requirements

This folder turns the MUJI reference screenshots and current MUSE screenshots into page-by-page implementation notes. The redesign includes the customer storefront and admin screens, keeps the name MUSE, and uses adjacent cedar accent color instead of copying MUJI red directly.

Boundary: use observable retail patterns such as compact typography, thin borders, product-first imagery, category navigation, and quiet utility. Do not copy MUJI logos, exact imagery, exact copy, or proprietary trade dress.

Spec Pages

Global Shell

Header, promo bar, category navigation, search, account actions, footer, practical link columns, and admin shell relationship.

Home

Converts the current editorial landing page into commerce modules: hero promo, category rail, seasonal rows, story cards, and product cards.

Catalog

Maps /products to collection category tiles, product-grid behavior, compact cards, filters, sort, and loading states.

Product Detail

Maps /products/$slug to gallery, purchase panel, variant buttons, quantity stepper, accordions, reviews, and product information sections.

Cart Checkout

Maps /cart, /checkout, and /payment/$orderNumber to compact order rows, forms, order summary, coupon, and payment states.

Account Auth

Maps login, register, account, order list, and order detail to a quieter retail account workspace with consistent forms and access states.

Admin

Maps the admin route family to a dense operational MUSE system: module nav, KPI bar, tables, forms, media picker, and access states.

Implementation Rules

Keep Routes Focused

Route files should load data, handle mutations, and compose small components. Move repeated view pieces into components before a route grows too much.

Start With Tokens

Update typography, color, borders, spacing, button, input, and card defaults before page-specific redesign work.

Do Storefront First

Build global shell, home, catalog, and PDP foundations, then bring cart, account, payment, and admin into the same system.

Reference docs only. No production code changed by these specs.
