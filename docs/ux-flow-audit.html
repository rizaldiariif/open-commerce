UX audit and implementation status, 2026-06-13

Muse Commerce UX, Flow, Edge Case, and Defect Audit

This report inventories the current app behavior, traces each major user and admin flow, lists edge cases, calls out likely defects, and proposes simple quality-of-life fixes. It is based on the current React routes, Convex functions, schema, styles, README, and launch docs.

Highest Priority Findings

  1. Payment and protected routes render tiny loading placeholders first. This causes the blank/flicker feeling, especially after checkout redirects to /payment/$orderNumber.
  2. Several protected routes call Convex queries that throw on unauthenticated users. Without route-level error UI, this can produce blank or harsh error states instead of clear login prompts.
  3. Checkout has a backend coupon preview query, but the UI does not use it. Coupon errors arrive too late, after the user submits the whole checkout form.
  4. Admin product creation is split across Products, Media, Variants, and Inventory. The app works, but the workflow is hard to discover and easy to abandon.
  5. Some admin content/settings fields are editable but are not fully reflected in the storefront or admin UI, including homepage featured category slugs, homepage banner images, footer text, and settings such as checkout enabled.

Payment retry behavior exists: a customer can create a new invoice after a failed or expired payment if the order still belongs to them, the order is retryable, and stock can be reserved again. The UX does not explain those conditions.

Detailed Feature Flow Audit

1. Register, Login, Profile Sync, Sign Out

Routes: /register, /login, global AuthStatus. Registration and login use Convex Auth, then ensureCurrentUserProfile creates or updates a customer profile.

  • Successful login redirects to the requested path or account.
  • Successful register redirects to account after profile sync.
  • Sign out redirects home.
  • Wrong credentials display inline error text.
UX Auth loading

2. First Superadmin Setup

Route: /setup. Signed-in first user submits SETUP_TOKEN. Backend disables bootstrap once any superadmin exists.

  • Invalid token returns an inline error.
  • Missing token configuration returns a backend error.
  • Already bootstrapped state links to admin.
  • Setup remains in global nav even when disabled.
UX Wayfinding

3. Storefront Homepage

Route: /. Loads site settings, published homepage content, banners, and featured products. If no content is published, defaults are used.

  • Missing media is hidden gracefully.
  • No active products shows an empty state.
  • Footer text is editable in admin but not rendered here.
  • Featured category slugs are stored but not used for products.
Defect UX

4. Product Listing

Route: /products. Lists active products and active categories with current price, image, and stock availability.

  • Archived and draft products are not shown.
  • Categories are displayed but are not clickable filters.
  • No search, sort, category filter, or stock filter exists.
  • Loading state is a small text page, causing visual flicker.
UX Catalog discovery

5. Product Detail and Add to Cart

Route: /products/$slug. Shows product media, variants, price, stock, quantity, and add-to-cart.

  • Archived or unavailable products return "Product not found."
  • Out-of-stock variants disable add-to-cart.
  • Signed-out users should see login, but auth loading can show add-to-cart first because only current === null is checked.
  • No pending state on add-to-cart, so repeated clicks are possible.
  • Success message does not offer "View cart" or "Checkout".
Defect UX

6. Cart Review

Route: /cart. Signed-in customers can review cart items, update quantities, remove items, and continue to checkout.

  • Signed-out users get a login prompt.
  • Invalid products or insufficient stock block checkout.
  • Quantity input uses defaultValue, so it can feel stale after reactive updates.
  • Cart does not consider checkoutEnabled, so it can link to checkout even when checkout is disabled in settings.
  • No per-item pending state, optimistic update, or undo after remove.
Defect UX

7. Checkout

Route: /checkout. Loads contact, saved addresses, cart details, and settings. Submitting creates an order, reserves stock, reserves coupon usage, creates a Xendit invoice, then navigates to payment.

  • Stock changes are revalidated on order creation.
  • Invalid coupons fail at submit time.
  • Backend supports coupon preview, but UI does not use it.
  • If invoice creation fails, the order may exist and the cart is already converted. Retry is possible from payment/order, but the user is not guided clearly.
  • Checkout page after redirect starts from a loading shell.
UX Late validation

8. Payment Handoff and Retry

Route: /payment/$orderNumber. Shows order items, totals, payment status, and the Xendit invoice link.

  • Pending payment with an active checkout URL shows "Pay with Xendit."
  • Pending payment with expired local URL can create a new invoice.
  • Failed or expired payment can retry if stock can be reserved again.
  • Paid, refunded, and cancelled orders cannot be paid again.
  • No countdown, payment timeline, webhook status, or clear retry explanation.
  • Initial SSR response is only "Loading order", so the redirect feels blank before hydration/data arrives.
UX Retry explanation

9. Customer Account and Orders

Routes: /account, /account/orders, /account/orders/$orderNumber. Customers can view their account, order list, order items, payment state, and shipment state.

  • /account has a friendly login-required state.
  • Nested order routes use queries that throw when not signed in.
  • Order statuses are raw text, not readable status badges.
  • No tracking link button even when tracking URL exists.
  • No reorder, contact support, invoice copy, or cancellation guidance.
Defect UX

10. Admin Shell and Navigation

Routes under /admin. Admin module pages call requireAdmin and getWorkspace.

  • Authorized admins see KPI counts and module tabs.
  • Unauthorized users should see a friendly admin access screen.
  • getWorkspace can throw while requireAdmin is still resolving, creating possible error/blank states.
  • Every admin tab loads one large workspace payload, which can contribute to flicker and slow refreshes.
Defect UX

11. Admin Products and Variants

Route: /admin/products. Admins can list products, edit products, archive products, list variants, create/edit variants, and deactivate variants.

  • Backend validates slugs, duplicate slugs, SKU uniqueness, money, and stock.
  • Admins can activate products without image, active variant, or stock.
  • Product images are selected by filename from existing media only.
  • Variant options use comma text syntax like Size:M, Color:Black.
  • Archive/deactivate have no confirmation or undo.
  • The route file combines product list, product form, variant list, and variant form, making future UX work harder.
UX Admin workflow

12. Admin Categories

Route: /admin/categories. Admins can create, edit, delete, or deactivate categories.

  • Deleting a category used by a product deactivates it instead.
  • Self-parenting is rejected.
  • No confirmation explains delete versus deactivate behavior.
  • Parent hierarchy is not visualized.
  • Category image uses the same media dropdown issue as products.
UX

13. Admin Inventory

Route: /admin/inventory. Admins view variant stock and record append-only inventory adjustments.

  • Negative stock after adjustment is rejected.
  • Adjustment must be a non-zero integer.
  • Reserved stock is shown, but available stock is not emphasized.
  • No search/filter for variant selection.
  • Recent movements omit dates and actor context in the UI.
UX

14. Admin Media Library

Route: /admin/media. Admins can upload images to Convex File Storage, save media records, preview media, and soft delete media from pickers.

  • Upload failure shows an inline error.
  • Soft-deleted media disappears from pickers and public media URLs.
  • No inline upload from product/content forms.
  • No file preview before upload, dimensions, size warning, usage count, restore, or confirmation.
  • Server accepts content type sent by the client and does not validate image type beyond the browser accept attribute.
UX Validation

15. Admin Homepage Content

Route: /admin/content. Admins edit hero text, hero image, CTA, featured category slugs, banners, announcement, about text, footer text, and status.

  • Hero title is required.
  • Featured category slug format is validated.
  • Banner entry uses pipe-delimited text.
  • Banner image IDs exist in schema but are not editable in UI.
  • Featured category slugs are stored but not used by storefront query.
  • Footer text is stored but not rendered by the storefront shell.
  • No live preview or draft/published comparison.
Defect UX

16. Admin Coupons and Customer Coupon Use

Route: /admin/coupons. Backend supports percentage and fixed coupons with minimum subtotal, cap, usage limits, per-customer limits, active windows, and enable/disable.

  • Coupon code is normalized uppercase.
  • Checkout reserves coupon usage and expiry releases it.
  • Admin can create very large percentage values; discount is capped by subtotal, but the admin UI can still be misleading.
  • No admin "test coupon" preview.
  • No redemption detail list.
  • Customer checkout does not preview coupon validity or discount.
UX Validation clarity

17. Admin Email Templates and Email Events

Route: /admin/emails. Superadmins can edit templates. Email events are logged as queued, sent, or failed.

  • Missing Resend API key logs failed email events.
  • Inactive templates skip sending silently.
  • Unknown template variables render as blank strings.
  • No variable reference, rendered preview, test send, retry, or diff before saving.
  • HTML body editing is a raw textarea.
UX

18. Admin Settings

Route: /admin/settings. Superadmins edit store name, logo, favicon, support email, SEO fields, and pending payment expiry minutes.

  • Regular admins see disabled save behavior.
  • Support email and positive expiry are validated.
  • Schema includes currency, locale, checkout enabled, and maintenance mode, but UI does not expose them.
  • Logo/favicon use filename dropdowns without preview or upload.
Defect UX

19. Admin Orders, Shipment, and Refunds

Routes: /admin/orders and /admin/orders/$id. Admins can search/filter recent orders, inspect details, update shipment state, and record manual refunds.

  • Only paid orders can be fulfilled.
  • Fulfillment transitions are validated.
  • Manual refund does not call Xendit and records local ledger state.
  • Refund amount is not checked against order total or previous refunds.
  • A partial refund still marks payment status as refunded.
  • Shipment/refund submits have no try/catch, no pending state, and no confirmation.
  • Search filters only the latest 100 orders fetched from Convex.
Defect UX

20. Admin Activity Logs

Route: /admin/activity. Shows the most recent admin activity entries.

  • Activity is append-only for important admin actions.
  • Only recent activity is visible.
  • Metadata, actor names, filters, and linked targets are not shown.
  • No empty state if there are no records.
UX

21. Xendit Webhooks, Expiry, and Cron Cleanup

Convex HTTP route: /api/xendit/webhook. Webhooks are token checked, normalized, deduped, and applied to order/payment, stock, and coupon state.

  • Paid webhooks mark payment/order paid, reduce stock, consume reserved coupons, and send emails.
  • Failed/expired webhooks release stock and coupon reservations.
  • Duplicate events are stored but do not reapply state.
  • Rejected webhook events are stored, but no admin UI exposes them.
  • Retry after failed/expired payment relies on the 10-minute cron for eventual expiry cleanup if a fresh scheduled expiry is not created.
UX Operational visibility

22. Health Checks and Launch QA

Route: /api/health. Convex also has health:check. Launch QA docs describe manual smoke tests.

  • Web health route returns static service and timestamp JSON.
  • It does not verify Convex connectivity, auth, Xendit, Resend, or storage configuration.
  • Manual QA exists in docs, but the app has no admin launch readiness dashboard.

UX Issues Found So Far

Area Issue Why It Feels Hard Simple Fix
Global navigation Customer, setup, and admin links are mixed in one flat nav. Users cannot tell what mode they are in. Separate store nav from account/admin nav. Hide setup after bootstrap.
Loading states Many routes render small text loading pages. Pages appear blank, then jump to real layout. Use skeletons matching the final layout and keep previous data while refreshing.
Feedback Most actions use inline messages only. Users miss success/failure and do not know what changed. Add app-level toast/snackbar plus field-level errors where needed.
Forms Raw text formats for variant options and homepage banners. Users must learn hidden syntax. Replace with repeated structured rows and simple add/remove buttons.
Admin product creation Product setup requires media upload first, then product, then variant, then inventory. Publishing a product is a multi-tab scavenger hunt. One product editor with sections: basics, media, variants, stock, SEO, publish.
Media Pickers show filenames, not thumbnails. Admins cannot confidently pick the right image. Thumbnail picker with search, selected preview, and inline upload.
Checkout Coupon errors happen after full submit. Users fill the whole form before learning discount failed. Apply/preview coupon before final payment step.
Payment Retry rules are hidden. Expired payment looks scary even though retry exists. Show explicit status copy, retry availability, and stock caveat.
Statuses Status values are raw text like pending_payment. Important state is not scannable. Status badges with labels, color, and short descriptions.
Tables on mobile Admin/customer tables rely on horizontal scroll. Important actions can be off-screen. Use responsive list rows/cards for small screens.
Dangerous actions Archive, delete, soft delete, deactivate, and refund have no confirmation. Admins can make destructive changes accidentally. Confirmation modal with consequence text and safer labels.
Admin order work Shipment and refund forms do not show pending or errors. Admins can click repeatedly and may not know a save failed. Disable buttons while saving, show errors, add confirmation for refunds.
Email templates No rendered preview or variable helper. Superadmins can break emails without seeing the result. Preview pane, variable list, and test-send button.
Admin dashboard Default admin route jumps to products. Admins do not get a "what needs attention" overview. Create a small dashboard: paid orders to fulfill, low stock, failed emails, recent payments.

Proposed Solutions

Immediate UX Fixes

  1. Add a shared notification/toast component and use it for product, cart, checkout, admin, media, order, and settings actions.
  2. Add route-level pending and error components, starting with payment, checkout, customer orders, and admin orders.
  3. Replace payment loading text with a full payment skeleton and immediate post-checkout confirmation state.
  4. Add pending states to all mutations that can be clicked more than once: add-to-cart, cart update/remove, product save, media delete, shipment save, refund save, coupon save.
  5. Convert raw status strings to shared labels and badges.

Product/Admin Workflow Fixes

  1. Build a focused product editor component with tabs or sections: Basics, Media, Variants, Inventory, SEO, Publish.
  2. Add inline media upload to product, category, content, logo, and favicon fields. On successful upload, select the new asset.
  3. Replace media dropdowns with thumbnail pickers.
  4. Add a publish readiness checklist: image, category, active variant, stock, price, SEO optional.
  5. Replace variant option text syntax with structured option rows.

Checkout and Payment Fixes

  1. Use previewCoupon in checkout and display applied discount before order submit.
  2. Show checkout disabled state in the cart before users click checkout.
  3. On payment page, show invoice expiry countdown and clear retry copy.
  4. Require a usable Xendit invoice URL before treating invoice creation as successful.
  5. If invoice creation fails, keep the user on a recovery page with "Try creating invoice again" and "View order" actions.

Data Loading and Flicker Fixes

  1. Split admin.getWorkspace into module-specific queries so each tab only reacts to data it needs.
  2. Gate protected data queries behind confirmed auth/access state.
  3. Add TanStack route loaders or pending components for routes that currently paint blank loading shells.
  4. Keep previous data visible during refresh when possible.

Operational Safety Fixes

  1. Validate manual refund amount against remaining refundable total.
  2. Add confirmation dialogs for refund, archive, delete, deactivate, and soft delete actions.
  3. Expose webhook events, failed emails, and payment failures in an admin operations view.
  4. Add indexed or paginated order search before order volume grows.

Suggested Implementation Plan

Phase Scope Why First
1 Shared toast, pending buttons, route error UI, payment skeleton, auth-gated protected queries. Biggest perceived quality improvement with the smallest product model change.
2 Payment retry copy, coupon preview, checkout disabled visibility, Xendit invoice URL validation. Reduces failed-checkout anxiety and fixes real recovery gaps.
3 Inline media upload, thumbnail media picker, product publish readiness checklist. Directly solves the hardest admin product workflow.
4 Structured forms for variants, banners, emails, and coupons. Removes hidden syntax and late validation errors.
5 Split admin workspace queries, improve order search, add operational dashboards. Improves performance, flicker, and long-term admin scalability.

Keep each route file focused on one route-level responsibility. For the bigger screens, extract small local components or shared components instead of continuing to grow route.tsx files.
